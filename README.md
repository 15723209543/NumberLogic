# NumberLogic / 数字推理工坊

一个基于 **C++17、Visual Studio 2022和Win32 API** 开发的Windows 本地数字逻辑训练软件。项目主要实现通过 A/B 反馈完成数字猜测、约束推理和逻辑训练，并支持经典挑战与进阶闯关、离线 AI 对战及智能提示、历史复盘、成绩统计与 CSV 导出等功能，适合作为程序设计学习与非商业技术研究。

> **特别说明：**本项目以 Windows 原生桌面程序为主体，不依赖网页、服务器、EasyX 或网络模型 API；原始猜数字作业作为开发基础，后续进行了 AI 辅助扩展。

## 2. 项目简介

数字推理工坊是一款面向逻辑思维训练和 C++ 程序设计学习的本地益智软件，源于猜数字游戏课程实践。玩家通过 A/B 反馈逐步缩小答案范围，并可在不同模式中练习推理、与离线算法对战和复盘历史结果。项目仓库：https://github.com/15723209543/NumberLogic。

## 3. 已实现功能

### 3.1 基础功能

经典挑战：四位数字、十次机会；进阶闯关：逐关增加位数并继承机会；AI 推理对战：双方交替猜测；逻辑训练：自定义位数和次数、查看候选提示；辅助功能包括计时、清空输入、复制复盘、历史筛选、CSV 导出、成绩统计与软件设置。

### 3.2 设置与配置

训练位数可设为 3—6 位，机会为 5—20 次，默认四位十次；AI 有基础、进阶和高级三档，默认进阶；可设置深色页面背景。设置保存在 settings.txt 中，启动时读取并限制参数范围。

### 3.3 核心规则或业务功能

答案由 1—9 中互不重复的数字组成；数字和位置均相同记为 A，数字相同但位置不同记为 B。例如 3579 与 2517 的反馈为 1A1B。无效输入不消耗机会；全部位置正确时获胜，机会耗尽仍未猜中则失败。闯关成功后位数最多增至九位，猜中的该次不扣除继承机会，下一关额外增加十次机会（最多1024次）。

### 3.4 图形界面与交互

主窗口左侧为导航，首页展示欢迎语与规则；其他页面分别提供数字输入、提交、反馈、剩余机会、耗时、历史列表、设置和帮助。通过原生 Windows 控件接收鼠标及键盘输入。

### 3.5 计时、评分、排名或结果结算

记录完成对局的有效猜测次数与耗时；统计最近2000局的完成局数、玩家猜中局数、猜中率、成功局平均次数、最少猜测次数及最高成功关卡。对战记录的成功表示玩家猜中，不等同于对战胜负。

### 3.6 自动控制、机器人或外部引擎

AI 接收合法数字及 A/B 反馈，枚举并筛除不一致候选，再根据所选策略输出猜测；候选为空时返回空字符串并提示异常。训练提示使用同一推理模块，不直接读取谜底。

### 3.7 撤销、存档与历史记录

完成的玩家回合追加到 history.tsv，记录时间、模式、位数、关卡、次数、结果、耗时、答案及猜测过程；支持筛选、详细复盘、CSV 导出和确认后清空历史，不提供中途对局恢复。

### 3.8 自动化测试

tests/core_tests.cpp 覆盖规则、输入校验、900个随机数字、关卡继承、90局随机四位 AI 推理、九位枚举与筛选、历史保存、CSV、统计及设置。Linux 下可用 g++ 编译核心测试，运行时应使用独立临时目录以免清空实际历史。

## 5. 运行方法

### 5.1 使用 IDE 或工程文件运行

将工程解压至纯英文路径 → 使用 Visual Studio 2022 打开 NumberLogic.sln → 选择 x64 / Debug 或 Release → 生成解决方案（Ctrl+Shift+B）→ Ctrl+F5 运行。生成文件位于 bin/x64/Debug/NumberLogic.exe 或 bin/x64/Release/NumberLogic.exe。

### 5.2 使用命令行运行

在工程根目录的 Windows Developer Command Prompt 中执行 `msbuild NumberLogic.sln /p:Configuration=Release /p:Platform=x64`；编译完成后运行 `bin\x64\Release\NumberLogic.exe`，控制台模式运行 `bin\x64\Release\NumberLogic.exe --console`。Linux 核心测试编译命令为 `g++ -std=c++17 -O2 -Wall -Wextra src/main.cpp src/AI.cpp tests/core_tests.cpp -o core_tests`，将测试程序放到独立空目录后执行。

### 5.3 常见运行问题

若无法打开 obj 文件，先关闭 IDE，将工程移到纯英文路径，删除旧 .vs、obj、bin 后重新生成；若 Windows 安全策略阻止自编译 EXE，应检查具体拦截原因及设备管理策略，勿直接关闭全部安全防护。

## 6. 操作说明

### 6.1 鼠标或界面操作

首页：查看规则；经典挑战：输入并提交四位数字；进阶闯关：猜中后点击下一关；AI 推理对战：设置自己的谜底，玩家提交后点击 AI 回合；逻辑训练：通过智能提示查看候选数量及建议；历史与复盘：筛选、查看详情、导出或清空；成绩统计：查看各模式表现；软件设置：保存训练参数、推理难度及页面主题。

输入由 1—9 构成的互不重复数字，位数与当前模式一致；控制台模式使用 --console 参数启动，并根据提示输入 1 开始、0 退出或 1 重新开始。

## 8. 模块与类关系

### 8.1 main.cpp 程序入口

main() 初始化随机数种子；有 --console 参数时接入控制台并调用 consolegame()，否则调用 runUI() 进入 Windows 消息循环。

### 8.2 Round 游戏流程

Round::start() 初始化对局；submit() 检查输入并保存反馈，更新次数与胜负；getcount() 计算剩余机会；next() 执行闯关继承；reveal() 在结束时返回答案。

### 8.3 数字规则模块

main.cpp 中的 isdigit、iszero、issimilar、numbertoarray、isA、isB 负责原始规则；checknumber、judgeAB、getrandnumber 负责封装输入校验、反馈和随机答案生成。

### 8.4 UI.cpp 与 UI.h

UI.cpp 创建主窗口及控件、管理导航和消息回调，调用核心游戏和 AI 接口；UI.h 声明共享游戏结构、数据管理接口及 runUI()。

### 8.5 AI.cpp 与 AI.h

Solver 管理候选集合，getallnumber() 递归枚举，removenumber() 按反馈原地筛选，guessnumber() 根据难度选择下一候选；countscore() 计算反馈分组评分。

### 8.6 本地记录与设置模块

Store 通过 FILE 接口追加、读取、导出和清除记录；Settings 保存和读取训练参数、难度及背景设置；文件操作失败时返回状态供界面提示。

## 9. 数据结构设计

### 9.1 核心结构体

Feedback 保存 a、b；Attempt 保存 guess 与 result；Round 保存 randnumbers、digit、maxcount、level、count、history、state 与 mode；Record 保存完成对局数据；Stats 保存统计结果；Solver 通过 possiblenumber 数组及 numbercount 管理候选；Settings 保存训练参数。

### 9.2 模式与状态枚举

Mode 包含 Classic、Campaign、Duel、Practice；State 包含 Playing、Won、Lost，决定是否允许继续提交或进入下一关。

### 9.3 核心运行状态

当前谜底、数字位数、已使用次数、最大机会、当前关卡、历史反馈、候选数量、对战回合及完成状态，随开始、提交、AI 回合、下一关或重开操作更新。

## 10. 主要算法与实现思路

### 10.1 程序主流程

启动 → 初始化 → 选择模式 → 生成谜底 → 输入校验 → 计算 A/B → 更新次数及状态 → 未结束则继续猜测 / 已结束则保存结果 → 查看复盘、进入下一关或重新开始。

### 10.2 随机答案与 A/B 匹配

getrandnumber() 使用 rand()%9+1 逐位生成，遇到重复重新抽取；numbertoarray() 拆分数字；isA() 单循环比较同一位置，isB() 双循环比较不同位置的数字。由于数字互不重复，反馈不会重复计数。

### 10.3 候选集合约束筛选

getallnumber() 使用布尔标记数组递归生成合法排列；Solver::removenumber() 对每个候选计算与本次猜测之间的 A/B，保留与实际反馈相同者，并在原数组前部压缩候选。四位初始候选为3024个，九位为362880个。

### 10.4 合法性与边界检查

先判断字符串长度与数字字符，再检查零值和重复；合法后才更新回合记录。位数限制1—9，单局最大有效猜测限制1024，结束状态拒绝继续提交。

### 10.5 状态机设计

Playing 状态允许提交；反馈 A 等于位数时进入 Won，机会耗尽且未猜中时进入 Lost；闯关仅在 Won 后允许 next()；重新开始时恢复 Playing 并重置本轮数据。

### 10.6 自动决策或搜索算法

基础策略取首个剩余候选；进阶最多抽取20个候选作为猜测、高级最多48个；每次评分最多抽样1200个待选答案，用 ABcount[10][10] 记录反馈分组，进阶最小化分组数量平方和，高级额外计入最大分组与样本量的乘积，选择评分最低的猜测。

### 10.7 日志与异常处理

非法输入直接提示并保留剩余机会；AI 无候选时提示推理异常；存储、导出、剪贴板操作失败时显示相应提示。历史清空操作需要用户确认。
